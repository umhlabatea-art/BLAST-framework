> **Every output is a first draft.** Your craft and the client's brand voice are
> the deliverable. Verify every claim against the client's substantiation before
> shipping — see `DISCLAIMER.md`. Replace every `[BRACKET]`; delete _italic_
> guidance.

## Shared inputs (paste into any prompt)

The better your research, the better the copy. Keep this block handy:

```
Product: [WHAT IT DOES IN ONE LINE]
ICP (ideal customer): [ROLE + COMPANY TYPE]
Core problem it solves: [PROBLEM]
Differentiator (why it, not a competitor): [DIFF]
Voice-of-customer quotes: [1-3 REAL QUOTES IF YOU HAVE THEM]
Brand voice: [e.g. plain, confident, a little playful]
Proof I can substantiate: [METRICS/CASE STUDIES — only what's provable]
```

## 1. Lifecycle / onboarding email sequences

### 1.1 — Onboarding sequence

```
Write a 5-email onboarding sequence for new users of [PRODUCT].

Goal of the sequence: [ACTIVATION EVENT, e.g. "invite a teammate", "first report"]
Send cadence: [e.g. day 0, 1, 3, 5, 8]
[PASTE SHARED INPUTS]

For each email give: subject line (+1 alt), preview text, body (under 150 words),
one clear CTA. Each email drives toward the activation event and adds one new
reason to act. No unsubstantiated performance claims — use only the provable
proof above. Return as a table: # | day | subject | preview | body | CTA.
```

### 1.2 — Churn-risk / re-engagement email

```
Write a re-engagement email to a user who signed up but hasn't reached
[ACTIVATION EVENT] in [N] days. Empathetic, not guilt-trippy; remind them of the
one outcome they wanted; remove the friction with a single next step. Under 120
words. [PASTE SHARED INPUTS]
```

## 2. Feature-launch & announcement emails

### 2.1 — Feature launch email

```
Write a feature-announcement email for [FEATURE].

What it does: [FUNCTION]  ·  Who it's for: [SEGMENT]  ·  Why now: [REASON]
The job it makes easier: [JOB-TO-BE-DONE]
[PASTE SHARED INPUTS]

Lead with the outcome, not the feature. Subject (+2 alts), preview, body under
160 words, CTA to try it. Avoid hype adjectives; show the before/after.
```

---

## 3. Landing-page copy

### 3.1 — Landing page (hero to CTA)

```
Write conversion copy for a landing page for [PRODUCT / OFFER].

Primary conversion goal: [DEMO / TRIAL / WAITLIST]
[PASTE SHARED INPUTS]

Sections: Hero (headline + subhead + primary CTA), 3 outcome-led benefit blocks
(benefit → how → proof), social-proof section (placeholders for logos/quotes),
objection-handling FAQ (5 Qs), final CTA. Every claim tagged [PROVABLE] or
[NEEDS PROOF] so I know what to substantiate.
```

---

## 4. Ad copy

### 4.1 — Ad variations

```
Write [NUMBER] ad variations for [CHANNEL, e.g. LinkedIn, Google Search] for
[PRODUCT]. Vary the angle: pain-led, outcome-led, and social-proof-led.
Constraints: [CHAR LIMITS PER FIELD]. [PASTE SHARED INPUTS]
For each: headline(s), primary text, CTA. Flag any claim that needs
substantiation before it can run.
```

---

## 5. SEO content briefs

### 5.1 — SEO article brief

```
Create an SEO content brief for the target keyword "[KEYWORD]" for [PRODUCT]'s
blog. Search intent: [INFORMATIONAL/COMMERCIAL]. Include: recommended title (+2
alts), meta description, H2/H3 outline, key questions to answer, entities/terms
to include, internal-link suggestions, target word count, and the single CTA. Do
not write the article — brief only.
```

---

## 6. Social calendars

### 6.1 — Two-week social calendar

```
Build a 2-week B2B social calendar for [PRODUCT] on [PLATFORMS].

Themes/pillars: [e.g. education, customer wins, product, POV]
Cadence: [POSTS PER WEEK]
[PASTE SHARED INPUTS]

Return a table: date | platform | pillar | hook | post copy | asset idea. Mix
formats; no more than 1-in-4 posts is directly promotional. Keep claims provable.
```
