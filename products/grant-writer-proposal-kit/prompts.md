# Grant Writer Proposal Kit — Prompt Pack (Core)

> **Every output is a draft built from _your_ real data.** Never let the model
> invent statistics, outcomes, citations, or program facts — a fabricated figure
> in a funder proposal is a credibility and compliance risk. Mark anything
> unverified with `[VERIFY]`. See `DISCLAIMER.md`. Replace every `[BRACKET]`.

---

## Shared inputs

```
Organization: [NAME + ONE-LINE MISSION]
Population served: [WHO]
Program: [NAME + WHAT IT DOES]
Real data I can cite: [OUTCOMES, #s SERVED, EVALUATION RESULTS — provable only]
Funder: [NAME + STATED PRIORITIES]
```

---

## 1. Letters of inquiry (LOIs)

### 1.1 — Letter of inquiry

```
Write a letter of inquiry to [FUNDER] for [PROGRAM].

Amount requested: [AMOUNT]  ·  Funder priorities: [PRIORITIES]
[PASTE SHARED INPUTS]

One page. Structure: hook tied to the funder's priorities → the need (with real
data) → our program and fit → requested amount and expected impact → invitation
to submit a full proposal. Warm, specific, no filler. Use only the data provided;
mark anything I still need to confirm with [VERIFY].
```

---

## 2. Needs / problem statements

### 2.1 — Needs statement

```
Write a needs (problem) statement for a grant proposal.

The problem: [PROBLEM]
Who is affected and how: [POPULATION + IMPACT]
Local/contextual data I'm providing (use only these): [DATA + SOURCES]
Gap our program fills: [GAP]

Make it evidence-based and urgent without being hyperbolic. Every statistic must
trace to a source I provided — do not add or estimate figures. Cite sources
inline as [SOURCE: ...]. Flag any claim lacking a source with [NEEDS SOURCE].
```

---

## 3. Program design & goals/objectives

### 3.1 — Goals & SMART objectives

```
Turn our program description into clear goals and SMART objectives.

Program: [DESCRIPTION]
Intended outcomes: [OUTCOMES]
Timeframe & scale: [DURATION, # SERVED]

Produce: 1-3 goals (broad) and, under each, 2-4 SMART objectives (specific,
measurable, achievable, relevant, time-bound) with the metric and target for
each. Keep targets realistic to the scale I gave — do not inflate.
```

### 3.2 — Logic model / activities-to-outcomes

```
Draft a simple logic model for [PROGRAM]: Inputs → Activities → Outputs →
Outcomes (short/medium/long term). Use only the activities and outcomes I
provide: [DETAILS]. Present as a clean table.
```

---

## 4. Budget narratives

### 4.1 — Budget narrative

```
Write a budget narrative that justifies each line of our project budget.

Budget lines (amount + purpose): [LINES]
Total request: [AMOUNT]  ·  Match/in-kind if any: [DETAILS]

For each line, explain what it funds and why it's necessary to achieve the
objectives. Reasonable, clear, tied to program activities. Do not add line items
or change amounts I didn't provide. Flag anything needing a cost basis with
[VERIFY].
```

---

## 5. Funder research summaries

### 5.1 — Funder fit summary

```
Summarize the fit between our organization and this funder from the information I
provide. Do NOT invent facts about the funder — use only what I paste.

Funder info (from their site/990/guidelines): [PASTE]
Our program: [SUMMARY]

Output: funder priorities, typical grant size/type (only if stated), alignment
with our program, any eligibility flags, and 3 tailoring recommendations for our
proposal. Note anything I should verify directly with the funder.
```

---

## 6. Impact / final reports

### 6.1 — Grant impact report

```
Write a final/interim report to [FUNDER] on the funded project using our real
results.

Objectives (as funded): [OBJECTIVES]
Actual results (real data only): [RESULTS vs TARGETS]
Stories/qualitative outcomes: [ANONYMIZED, WITH CONSENT]
Challenges & learnings: [HONEST]
Use of funds: [SUMMARY]

Structure: progress against each objective (target vs actual) → impact story →
challenges & adaptations → financial summary → thanks & next steps. Be honest
about any objective not fully met — funders value candor. Use only provided data;
flag gaps with [VERIFY].
```
